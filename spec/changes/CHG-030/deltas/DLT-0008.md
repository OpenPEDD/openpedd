# DLT-0008 · What a loose item is the change's

| Field | Value |
|---|---|
| `target` | `FR-VEW-09`, [loose items](../../../modules/views/prd.md#loose-items) |
| `op` | `MODIFIED` |

| `stage` | `build` |
| `change` | `CHG-030` |
| `reason` | The PRD says it fails on what the change adds or touches, not how either is told; nor which view marks an ID defined nowhere, which can be cited from any document |
| `alternative` | Fail only on items in files the change edits: a definition removed would leave its citations loose in files nobody touched |
| `revert` | `packages/cli/src/check.mjs`: `looseCheck`; `packages/cli/src/cli.mjs`: `looseState`; `packages/reader/src/views/index.mjs`: `viewOfPath` |

**Proposed text:** `pedd check` builds the views at `--against` too. A loose item is the change's when
it is not among the base's (same view, kind, item, file and message) or its file changed since; one on
another change branch is that change's; without git, every one is. An ID is defined by a title or
heading `ID · …`; for `FR`, `NFR`, `AC`, `Q`, `PRC`, `INT` and `EVT`, by a row whose first cell is the
ID; a question by the decision that closes it; a change by its folder or its history; an ID by the
`ADDED` delta that adds it; and by a link to another spec. An ID defined nowhere is marked in the view
of the document that cites it: decisions, domain, Business Map, modules, changes, the two security
foundations; any other document in `context`.
