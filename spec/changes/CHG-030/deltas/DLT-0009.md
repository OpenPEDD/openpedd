# DLT-0009 · Where the views find their sources

| Field | Value |
|---|---|
| `target` | `ARCH-22`, [how each kind reads its source](../../../foundations/architecture/views.md#how-each-kind-reads-its-source) |
| `op` | `MODIFIED` |
| `type` | `assumption` |
| `stage` | `build` |
| `change` | `CHG-030` |
| `reason` | Foundations live in `foundations/<name>/` with no name fixed; the code index, `.pedd/stack.json` and the workspace graph are specified, not built, so their files have no fixed shape yet |
| `alternative` | Leave `security`, `context` and `code` empty until each format is specified |
| `revert` | `packages/reader/src/views/prep.mjs`: `foundationDoc`; `context.mjs`: `stackOf`; `code.mjs`; `packages/cli/src/sources.mjs` |

**Proposed rows:** a foundation is the document under `foundations/` whose `title` is its name
(`Roles & Permissions`, `Security Policy`, `Integrations`), else `roles/`, `security/` or
`integrations/`. A code index entry is a file with a `#` name and `## Where`, `## IDs` and
`## Symbols`: names of other entries in code spans, one requirement per line with its files, and the
symbols ranked, of which the view shows eight. The stack is a list of `{ name, kind, file, component }`.
The workspace graph is each component's `package.json` dependencies.
