# DLT-0007 · The shape of `views.json` beyond its example

| Field | Value |
|---|---|
| `target` | `ARCH-22`, [`views.json`](../../../foundations/architecture/views.md#viewsjson) |
| `op` | `MODIFIED` |
| `type` | `assumption` |
| `stage` | `build` |
| `change` | `CHG-030` |
| `reason` | `security` has two matrices (who does what, what protects each table), `business` two (as-is, to-be) and `prd` one per PRD; `FR-VEW-03.AC1` asks every edge for its file and line, and the example's edges have neither |
| `alternative` | One matrix per view, and the second drawn as a graph |
| `revert` | `packages/reader/src/views/common.mjs`: `view` |

**Proposed rows:** `matrix` is a list, each `{ id, title, group, rows, cols, cells, at, line }`, or
`null`. Every edge has `at` and `line`, like a node. A node may carry what its item holds beyond its
label, as written: an entity's `what` and `fields`, a state's `means`, a step's `role`, a component's
`stack`, a trace link's `freshness`. A loose item has `message`, what is loose, beside `says`, the item
as written.
