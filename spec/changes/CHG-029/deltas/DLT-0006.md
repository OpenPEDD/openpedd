# DLT-0006 · How `pedd branch` and the branch check work

| Field | Value |
|---|---|
| `target` | `ARCH-06`, [creating a branch](../../../foundations/architecture/branches.md#creating-a-branch) |
| `op` | `MODIFIED` |
| `type` | `assumption` |
| `stage` | `build` |
| `change` | `CHG-029` |
| `reason` | `pedd branch <issue>` reads the tracker, whose adapter is not built; and git cannot tell which of two branches sharing commits was cut from the other |
| `alternative` | Wait for the tracker adapter before any `pedd branch` |
| `revert` | `packages/cli/src/branch.mjs` and `packages/cli/src/branch-check.mjs` |

**Proposed rows:** until the tracker adapter, the kind is named: `pedd branch change <slug> [--track]`
(also `request`), `design <change>`, `architecture <change>`, `task <change> <task>`, `edit <change>`,
`rename <change> --track <track> [--key <key>]`. A hotfix is numbered like any change. The branch
check fails when the head is not named as a work branch, targets another branch than its kind's, holds
two new `changes/<CHG>/` folders, or shares commits the target lacks with another work branch other
than its own design, architecture, task and edit branches; then both branches are named. `cover`
has no branch prefix in `ARCH-06`: `pedd branch` refuses it until one is decided.
