# DLT-0004 · How the reader reads the Business Map

| Field | Value |
|---|---|
| `target` | `ENT-02`, the `Business Map` row ([foundation](../../../foundations/domain/foundation.md)) |
| `op` | `MODIFIED` |
| `type` | `assumption` |
| `stage` | `build` |
| `change` | `CHG-029` |
| `reason` | `map`'s business mode names the two files and what each holds, not how; the Cloud's business map screen needs one form to read |
| `alternative` | One file with an as-is and a to-be column per process |
| `revert` | `packages/reader/src/business-map.mjs` |

**Proposed text:** each file has one `##` section per thing it holds, under the names in
[`map`](../../../modules/map/prd.md#business-mode): `People` · `Processes` · `Tools and spreadsheets` ·
`Pains` in the as-is, `People` · `Processes` · `Modules` · `Order` in the to-be. Each is a table. A process
is a row whose `ID` holds `PRC-nn`, or a `### PRC-nn · Name` heading with a `Field | Value` table and
its steps. In the to-be, its `Mark` column is `kept`, `changed` or `taken` and its `Module` column the
module that takes it. The order may be a numbered list.
