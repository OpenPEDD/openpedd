# DLT-0005 · The reader reports what it cannot read

| Field | Value |
|---|---|
| `target` | `ARCH-20`, [what it does](../../../foundations/architecture/reader.md#what-it-does) |
| `op` | `MODIFIED` |
| `type` | `assumption` |
| `stage` | `build` |
| `change` | `CHG-029` |
| `reason` | A frontmatter read tolerantly gave an empty status without a word; the Cloud's map build had to check it on its own. Two readings of a spec, against `DEC-26` |
| `alternative` | `readSpec` throws on the first broken document |
| `revert` | `packages/reader/src/markdown.mjs` (`parseFrontmatter`) and `packages/reader/src/spec.mjs` (`problems`, `leastAdvanced`) |

**Proposed rows:** the model carries `problems`: each frontmatter not closed, not on the first line,
with a line that is not `key: value`, a key set twice or a quote not closed, and each history line
that is not JSON, with its path and line. The data is still given; the caller decides what fails.
A PRD carries its least advanced requirement in the order of [`ENT-03`](../../../foundations/domain/requirement.md#lifecycle),
with `changing` just below `live` and `deprecated` holding nothing back.
